决策记录：seed `e1ca1482`（mode operate），用户在四张全卡里选了挑战牌 `challenger-zoo-map`（动物园与植物园导览图）。落选：菜市场价签（骰子指定）、营养成分表（模型推荐）、厨房秤液晶（备选）、行业标准卡片（standing exit）。裁决理由见 `.impeccable/decision-e1ca1482.json`。

## 1. 任务与人

- 谁：开发者本人，三十多岁上班族、有小孩；手机竖屏单手，一天三四次、每次半分钟。家人偶尔借用特殊人群模式。
- 模式：Operate。来的人在做事（记一笔、看余量、挑晚餐），表达永远不能遮住任务、状态和熟悉的操作方式。
- 为什么是这张图：带小孩的父母周末都摸过折成八折的导览图，识别度高；它的语法（一块色地占屏、岸线分区、胶囊控件、单一字体单字重）足够完整，能覆盖导航、内容、控件和状态。

## 2. 结果与证据

- 主任务：一屏内看清「还可以吃多少」并完成一次录餐；次任务：接受或换掉一餐推荐；再次：周度回顾。
- 成功：操作路径与现在一致或更短；数字对照（已吃 / 目标）比现在更醒目；一眼能认出这不是苹果健康那一套。
- 真材实料：333 道菜、234 食材、规则引擎给出的理由文案。没有菜品照片，不编造；色地里不放图，放文字与数字。

## 3. 选定方向：把一天的饮食画成一张导览图

**世界语法（来自目录卡，逐条译到产品）**

- 材质与色：平涂、无颗粒、无渐变、无投影。米色纸底当「水面」，苹果绿色地当「陆地」，墨色做正文。珊瑚、太阳黄、池塘蓝是标签与控件色，也承担三大宏量的数据色（见第 7 节约束）。
- 字体：一款无衬线，一个字重贯穿标题、正文、按钮、数字。中文用系统 PingFang / HarmonyOS Sans，不做负字距；拉丁数字可以收紧。标题行距 0.95 左右，正文照常。
- 拓扑：每屏一块主色地，岸线从两侧出画；色地可以在中间「开口」，露出纸底当水。所有分区靠岸线，不靠卡片边框与投影。
- 控件与状态：控件是胶囊，边缘微微起伏像岸线；一颗圆形小片骑在胶囊尾端，激活时滑到头端。禁用是描边空胶囊，选中是实心色地。
- 动效：只有一处签名动效，岸线与色地的变化 0.4 秒、带一次过冲；其余控件反馈 150～250 毫秒。滚动时岸线连续重绘（单一 SVG path 形变）。尊重 prefers-reduced-motion：关掉形变与过冲，只保留不透明度。

**签名时刻：今日页的「湖」**

今日页的主色地是「今天」这块陆地，从左上角涨到右下，岸线从右侧和底部出画。色地中间开口，露出纸底：那一块水就是「还可以吃的 833 千卡」。吃得越多，陆地越涨、湖越小；超标时湖消失，岸线用珊瑚色描一圈并写字「已超出 120 千卡」。这一处把「摄入 / 目标」这个产品机制画成了地形，而不是圆环。

## 4. 范围与边界

- 保留：底部四页签（今日 / 推荐 / 分析 / 我的）、所有功能与文案、录餐抽屉的交互、数据与导入导出。
- 浅色为主。深色 token 保留但先不投入；若做，只做陆地与水的两级换色，不做黑底。
- 反目标：不能像营销落地页（不要大标题口号、不要照片）；不能靠颜色单独表意；不能出现同类应用的白卡片加投影。
- 这一轮不改代码。

## 5. 状态与范围

- 首次运行：没有档案时，导览图只有水面和一块小岛「先填一下身体数据」，胶囊按钮居中。
- 空日：陆地很小，湖很大，岸边一句「这一天还没有记录」，胶囊「记一笔」。
- 正常：1～4 餐、每餐 1～6 条，菜名 2～12 字，数字 0～4 位。
- 超标：湖消失，岸线珊瑚描边，状态文字必现。
- 记录不全的日子（分析页 `.bar.dim` 语义）：柱子改为描边空心，不用浅色代替，配文字说明。
- 加载与保存：本地同步，无加载态；toast 撤销保留，样式改成胶囊。

## 6. 各屏布局与交互

- **今日**：上半屏陆地 + 湖（余量数字与「还可以吃」放在湖里，墨色）。陆地上沿岸排三条宏量：蛋白 / 脂肪 / 碳水，条形平涂，长度按真实克数等比，目标处一根细岸线。下半屏是水面上的「地名式」记录：餐次是地名标签（早餐 · 316），菜是地名下的小字；每餐尾端一颗胶囊「添加」。右下悬浮加号改成黄色胶囊「记一笔」，圆片在尾端。
- **推荐**：三块色地（早 / 午 / 晚）自上而下，各占一屏的三分之一，岸线互相咬合；已吃的餐变成水面上只留地名。每块色地里是菜名与理由（理由是这个产品最独特的内容，放在色地里用墨色，不藏）。「换一换」是描边胶囊在岸线上，「照这个吃」是实心胶囊在色地下缘。
- **分析**：数据页，色地退成一条窄岸线在顶部，正文在水面上保证清晰。近 7 天柱图平涂，目标是一根岸线；近 4 周达标是 7 列小色块，达标绿、偏离黄、无记录描边空心，每种都配文字图例。日均 vs 目标保持横条，红字超标处加「超」字。结构建议按现有 `.finding` 结构，图标换成胶囊里的圆片。
- **我的**：设置是导览图背面的索引：分组标题为地名，选项为胶囊或分段控件（`.seg` 改成胶囊组）。说一句话录餐的服务商切换与 key 输入保持原逻辑。
- **录餐抽屉**：抽屉是一块从底部涨起来的色地，顶缘是岸线而非直线；搜索框是描边胶囊；结果列表在色地上；选中菜后条目「钉」到岸边并 0.4 秒过冲一次。拖拽关闭保持。
- **底部页签**：一条水面上的描边胶囊条，四个图标各带圆片；当前页圆片变成绿色地。

## 7. 约束与待定

**来自并行会话的交接要点（必须遵守）**

- 样式入口只在 `src/styles.css` 顶部的 token，明暗两套；组件只引用 token。这次换世界优先改 token，再改必要的结构类。
- 三大宏量色（蛋白红、脂肪蓝、碳水琥珀）已过色弱与对比度校验。译到导览图世界：珊瑚承担蛋白、池塘蓝承担脂肪、太阳黄偏琥珀承担碳水，三个色相保持分离，具体值落地时用 dataviz 的校验器重新过一遍，深色档亮度不拉高。
- 共享类名不改名：`.card .btn .pill .chip .seg .stepper .meter/.track/.fill .list-item .sheet* .toast .cal .finding`。可以改它们的样式，不要改它们的名字；确需改名同步 `src/ui/` 对应文件。
- 图表在 `src/ui/charts.tsx` 按容器宽度 1:1 绘制，文字用 token 色；`.chart .bar.dim` 是记录不全的日子，保留语义。
- 回归：`npm test && npm run build`。基线 56 个测试全绿、单文件构建 630 KB。落地后体积增长控制在 SVG 岸线路径与字体设置之内，不引入依赖。
